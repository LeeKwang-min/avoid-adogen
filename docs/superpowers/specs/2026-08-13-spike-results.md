# 스파이크 결과 (2026-08-13)

5차에 걸쳐 확인했다. 결론부터: **셀 배경색 페인팅을 버리고 SVG 이미지 방식으로 전환한다.**

## 1차 — 셀 페인팅 기본 검증

들여쓰기 공백 구간에 `Range`를 걸고 `backgroundColor`를 칠했다.

### S1 — 코드가 밀리지 않는가
**PASS.** 색띠가 들여쓰기 영역에만 그려지고 코드 텍스트의 가로 위치는 변하지 않았다. 설계의 핵심 전제가 성립한다.

### S2 — 들여쓰기 안내선 겹침
**다크 테마는 PASS, 라이트 테마는 FAIL.** 다크에서는 색띠가 안내선을 덮었다. 라이트에서는 안내선이 더 진해서 그림을 관통해 보인다. 알파를 올리면 완화되지만 완전히 없애려면 가독성을 해칠 만큼 진해져야 한다. **남는 한계로 수용하고 README에 안내선을 끄면 낫다고 적는다.**

### S3 — 선택 영역·현재 줄 하이라이트 겹침
확인하지 못했다. 칠해진 줄이 현재 줄과 겹치지 않아 관찰 기회가 없었다. 이후 이미지 방식으로 전환했으므로 이 항목은 무효가 됐다.

### S4 — 한 줄에 여러 색
**PASS.** 한 줄 안에서 4색이 열마다 번갈아 정상 표시됐다.

## 2차 — 셀 종횡비 실측

**설계 가정(1:2.5)이 틀렸다. 실측 1:3.4다.** (문자 폭 8.7px, 줄 높이 30px)

게다가 이 비율은 사용자의 `editor.fontSize`·`lineHeight` 설정에 따라 1:2~1:4로 변한다. 하드코딩한 도트 아트는 환경마다 다르게 찌그러진다.

이 종횡비에서 세로 7줄을 채우는 원은 가로 24셀이 필요한데, depth 8 삼각형의 최대 여백이 16칸이다. **원은 그릴 수 없다.**

## 3차 — 형태 3종 비교 (셀 페인팅)

구슬형 / 빔형 / 스파크형을 같은 화면에서 비교했다. 채도를 2배 올렸다.

결과: 빔형이 그나마 나았지만 **셋 다 임팩트가 없었다.** 8.7×30px 사각형 55개로는 "에너지파"로 읽히지 않고 흐릿한 얼룩으로 보인다. 방향성이 전달되지 않는 게 결정적이었다.

## 4차 — 렌더링 방식 3종 비교

| 방식 | 결과 |
|---|---|
| **A** `before` + `contentIconPath` + negative margin (공식 API만) | **FAIL** — 코드가 밀렸다. 빈 줄이 생기고 뒤 텍스트가 오른쪽으로 이동했다. 음수 마진 상쇄가 라인 박스 높이 변화를 막지 못한다. |
| **B** A + `textDecoration`에 `position: absolute` CSS 인젝션 | **PASS** — 이미지가 라인 박스에서 빠져나와 여러 줄에 걸쳐 그려지고 코드는 전혀 밀리지 않는다. |
| **C** 셀 페인팅을 삼각형 여백 전체에 방사형으로 (알파 상향) | 동작하지만 **B와 비교 불가.** 셀 방식의 최대치가 이 정도다. |

### B 방식의 성격

`textDecoration` 문자열에 `;`를 넣어 임의 CSS를 주입하는 **비공식 해킹**이다. VS Code가 이 값을 이스케이프하도록 바꾸면 깨진다.

수용하는 이유: 실패해도 이미지가 안 보이는 정도로 그치고 에디터가 망가지지 않는다. 이 트릭을 쓰는 익스텐션이 여럿 있어 갑자기 막힐 가능성이 낮다. 그리고 이 방식 없이는 컨셉 자체가 성립하지 않는다.

## 5차 — SVG 디자인 3종 비교

B 방식으로 고품질 SVG 3종을 비교했다. `feGaussianBlur` 필터가 data URI SVG에서 정상 동작한다.

- **클래식** (구체 + 뒤로 흐르는 스트림 5줄기 + 앞쪽 충격파 호 + 스파크) — **채택**
- **플레어** (수평 관통 광선 + 방사 광선 + 코어) — **채택**
- **소용돌이** (코어를 감는 나선) — 미채택

## 6차 — 캐릭터 추가와 자세 조정

`{{ink}}` 플레이스홀더로 캐릭터 선 색을 테마별로 주입하는 구조를 넣고, 자세를 세 번 고쳤다.

1. **팔꿈치·무릎 관절 추가** — 직선 팔이 처져 보였다. 관절을 넣었지만 팔이 더 내려가 실패했다.
2. **캐릭터를 아래로 이동** — 원인은 관절이 아니라 배치였다. 어깨가 파동권 궤적보다 위에 있으면 손을 궤적에 맞추려고 팔이 반드시 아래로 내려간다. 어깨 자체를 궤적 높이로 옮기고 팔을 수평 직선으로 만들자 몸통과 직각이 됐다.
3. **뒷다리 무릎 방향 반전, 팔에 곡률 추가** — 무릎을 안쪽으로 볼록하게 바꿔 버티는 자세를 만들고, 두 팔을 반대 방향으로 휘게 해 손 끝에서 모이는 타원형 고리를 만들었다.

배운 것: **정렬 문제는 관절이 아니라 기준점 배치에서 나온다.** 손을 목표 위치에 맞추려 팔 모양을 비틀기 전에 어깨가 어디 있어야 하는지를 먼저 봐야 했다.

## 미검증으로 남는 것

- **`light`/`dark` 안의 `before`가 실제로 적용되는지 확인하지 못했다.** 타입은 허용하고 다크 테마에서는 정상 동작하지만, 라이트 테마에서 캐릭터 색이 `#2b5f8f`로 바뀌는지는 눈으로 보지 못했다. 무시된다면 라이트 테마에서 캐릭터가 흐릿하게 보인다. 최상위에 다크용을 두었으므로 최악의 경우에도 이미지 자체는 나온다.
- **S3**(선택 영역·현재 줄 하이라이트 겹침)은 셀 페인팅 시절 항목이라 이미지 방식에서는 무효다. 이미지는 텍스트 뒤에 그려지므로 문제가 되지 않는다.

## 설계에 반영할 변경

1. **렌더링을 셀 페인팅에서 SVG 이미지로 전환.** `sprites`(도트 그리드), `palette`, `mergeCells`가 불필요해진다.
2. **`canvasFitter`의 역할 변경.** 셀 그리드 대신 삼각형의 여백 폭(ch)과 높이(줄 수)를 재는 계측기가 된다.
3. **티어별 고정 크기.** `width`/`height`가 `DecorationType`에 고정되므로 크기를 자유롭게 바꾸면 타입이 무한히 늘어난다. 티어당 하나의 크기·디자인으로 고정해 `DecorationType`을 3개로 유지한다.
4. **`palette` 설정 제거.** 색이 SVG 안에 있다.
5. **탭 들여쓰기 제약이 사라진다.** 셀 단위 제어가 필요 없으므로 탭 줄도 여백 폭만 알면 된다. 다만 `visualCols`와 문자 수가 다른 문제는 남으므로 v1에서는 계속 제외한다.
